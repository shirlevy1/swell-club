# בדיקות E2E

```
npm run test:e2e
```

מריץ שרת `next dev` זמני במצב הדגמה בלבד (`NEXT_PUBLIC_SWELL_DEMO=1`) בפורט 3100,
ונגדו מריצה את הבדיקות. לא נוגע במסד הנתונים האמיתי בשום מצב - גם אם יש מפתחות
Supabase אמיתיים ב-`.env.local` (יש כאלה, לפיתוח רגיל), מצב ההדגמה פשוט מתעלם מהם.

## למה רק בדיקה אחת

הבדיקה היחידה שקיימת כרגע (`checkin-persists-after-refresh.spec.ts`) מגינה על
תרחיש שכבר נשבר פעם אמיתית: צ'ק-אין נרשם, אבל רענון דף הראה בטעות "כבר לא חלק
מהקהילה" במקום את ההגעה שכבר נרשמה. זה המקום הכי טבעי להתחיל ממנו - לא ניסיון
לכסות את כל האתר.

## למה הצ'ק-אין "מוזרע" דרך API, לא דרך המצלמה האמיתית

זרימת הצ'ק-אין האמיתית (גם במצב הדגמה) דורשת מצלמה אמיתית וזיהוי פנים אמיתי
בתמונה - אין דרך סבירה לדמות את זה אוטומטית בלי קובץ וידאו עם פנים אמיתיות.
הנתיב `/api/test/seed-checkin` (קיים רק במצב הדגמה - 404 בכל מצב אחר, כולל
האתר האמיתי) קורא ישירות לאותה פונקציה שהמצלמה הייתה קוראת לה בסוף
(`checkInAction`), ומדלג רק על שלב הצילום עצמו. מה שהבדיקה באמת בודקת - האם
רענון דף שובר תצוגת נוכחות קיימת - לא תלוי בשלב המצלמה בכלל.
